# پنل وب Aether (غیررسمی)

**[English](README.en.md)**

یک پنل وب ساده (Next.js) برای اجرا و مدیریت کلاینت [Aether](https://github.com/CluvexStudio/aether) روی یک سرور. با یک دکمه تونل را وصل می‌کنید، لاگ و وضعیت را می‌بینید و در صورت نیاز یک آدرس SOCKS5 عمومی (با نام کاربری و رمز) برای اتصال از گوشی یا کامپیوتر می‌سازید.

> این پروژه **غیررسمی** است و وابسته به CluvexStudio نیست. نام و لوگوی Aether متعلق به سازندگان آن است (سیاست نام تجاری در ریپوی اصلی). اگر این پنل را عمومی منتشر می‌کنید، از آن‌ها اجازه بگیرید یا نام و آیکون را عوض کنید.

## امکانات

- شروع و توقف تونل با یک دکمه
- انتخاب پروتکل (MASQUE، WireGuard، Gool، MiM)، ترنسپورت، حالت اسکن، نسخه IP و پروفایل noize
- نمایش وضعیت، gateway، IP خروجی، مدت اتصال و لاگ زنده
- دکمه‌ی تست اتصال (از طریق `cloudflare.com/cdn-cgi/trace`)
- «دسترسی از بیرون»: انتشار پراکسی روی یک آدرس عمومی با نام کاربری و رمز تصادفی
- قفل با نام کاربری و رمز (Basic Auth) روی کل پنل و همه‌ی APIها

## نحوه‌ی کار

پنل باینری رسمی Aether (نسخه‌ی استاتیک musl) را از صفحه‌ی Releases ریپوی اصلی می‌گیرد، checksum را بررسی می‌کند و به‌صورت یک پروسه‌ی فرزند اجرا می‌کند. پراکسی SOCKS5 روی `127.0.0.1:1819` **داخل همان کانتینر** باز می‌شود. برای استفاده از بیرون باید از بخش «دسترسی از بیرون» استفاده کنید.

در Docker، باینری موقع بیلد نصب می‌شود (`AETHER_BIN=/opt/aether/aether`) و دکمه‌ی «نصب» لازم نیست.

## اجرا با Docker

```bash
docker build -t aether-panel .
docker run -d --name aether-panel -p 3000:3000 \
  -e PANEL_USER=admin \
  -e PANEL_PASSWORD='یک-رمز-طولانی' \
  -v aether-data:/data -e TMPDIR=/data/tmp \
  aether-panel
```

سپس `http://localhost:3000` را باز کنید. Volume اختیاری است ولی هویت WARP را بین ری‌استارت‌ها نگه می‌دارد (ثبت‌نام مکرر دستگاه توسط Cloudflare محدود می‌شود).

## دپلوی روی Railway

1. New Project ← Deploy from GitHub repo، و این ریپو را انتخاب کنید (Dockerfile خودکار شناسایی می‌شود).
2. در Variables این‌ها را بگذارید: `PANEL_USER` و `PANEL_PASSWORD`.
3. Settings ← Networking ← Generate Domain.
4. اختیاری: یک Volume روی `/data` بسازید و `TMPDIR=/data/tmp` را اضافه کنید.

## دپلوی روی Render

1. New ← Web Service، ریپو را وصل کنید و Runtime را **Docker** بگذارید.
2. Instance Type باید **پولی** باشد؛ پلن رایگان بعد از مدتی بی‌کاری سرویس را می‌خواباند و تونل قطع می‌شود.
3. Environment: `PANEL_USER` و `PANEL_PASSWORD`.
4. Advanced ← Health Check Path: `/healthz`.
5. اختیاری: Disk روی `/data` به‌همراه `TMPDIR=/data/tmp`.

## متغیرهای محیطی

| متغیر | الزامی | توضیح |
| --- | --- | --- |
| `PANEL_USER` | بله | نام کاربری پنل |
| `PANEL_PASSWORD` | بله | رمز پنل. اگر خالی باشد پنل هیچ‌چیز سرو نمی‌کند (وضعیت 503) |
| `AETHER_BIN` | خیر | مسیر باینری Aether (در Docker از قبل تنظیم شده) |
| `TMPDIR` | خیر | مسیر داده‌های زمان اجرا؛ برای ماندگاری روی Volume بگذارید |
| `BORE_SERVER` | خیر | رله‌ی ویژگی «دسترسی از بیرون» (پیش‌فرض `bore.pub`) |
| `PORT` | خیر | پورت پنل (Railway و Render خودشان تنظیم می‌کنند) |

نمونه در `.env.example`.

## اجرای محلی (توسعه)

نیاز: Node 22 و pnpm 10.

```bash
pnpm install
printf 'PANEL_USER=admin\nPANEL_PASSWORD=test\n' > web/.env.local
export AETHER_BIN=/مسیر/به/aether     # یا از دکمه‌ی نصب پنل (فقط Linux) استفاده کنید
pnpm dev
```

## نکات امنیتی

- بدون `PANEL_PASSWORD` قوی پنل را عمومی نکنید؛ هر کسی که به پنل برسد می‌تواند تونل را کنترل کند.
- «دسترسی از بیرون» از رله‌ی عمومی `bore.pub` استفاده می‌کند. رمز تصادفی دارد و با هر روشن‌کردن عوض می‌شود، ولی ترافیک دیگران از IP سرور شما خارج می‌شود. فقط وقتی لازم است روشنش کنید و لینک را به کسی ندهید.
- بعد از دپلوی، آدرس را در پنجره‌ی ناشناس باز کنید؛ باید رمز بخواهد.

## محدودیت‌ها

- **Vercel پشتیبانی نمی‌شود.** پنل یک پروسه‌ی طولانی اجرا می‌کند و وضعیت را در حافظه نگه می‌دارد؛ روی serverless این‌ها از بین می‌روند. از Railway، Render، Fly.io یا یک VPS استفاده کنید.
- دکمه‌ی نصب فقط روی Linux (x64 و arm64) کار می‌کند.
- حالت HTTP/3 به UDP نیاز دارد و روی بعضی هاست‌ها بسته است؛ پیش‌فرض HTTP/2 است.
- ترافیک از IP دیتاسنتر سرور شما خارج می‌شود.

## ساختار

```text
  proxy.ts          قفل Basic Auth و مسیر /healthz

  lib/              کنترل پروسه، نصب باینری، اشتراک (bore)
```
